# Skill: skill-verify

## 描述
验证经验沉淀的可复现性。当经验被沉淀写回后强行触发，让用户开启一个仅加载 Agent-RL 框架信息（无当前会话上下文）的新 Agent，完成相同任务。能完成说明经验可靠，完成不了说明经验需要迭代修改。

## 触发条件
- **强行触发**：每当 _reflector.md 协议完成经验写回（enhance 或 new 类型提案被接受并写回）后自动触发
- 用户显式要求验证经验可复现性时

## 行为规范
1. **触发提示**：经验写回后，向用户说明验证流程：
   - 本次沉淀的经验涉及什么任务
   - 请用户开启一个新 Agent（新会话），仅加载 Agent-RL 框架（skills/ 目录下的 MD 文件），不携带当前会话的任何上下文
   - 让新 Agent 完成相同的任务
2. **等待反馈**：等待用户反馈验证结果
3. **验证成功**：新 Agent 能靠框架+经验完成任务 → 经验可靠，流程结束
4. **验证失败**：新 Agent 无法完成任务 → 询问用户失败的具体原因（哪些步骤卡住、哪些信息缺失），触发反思迭代：
   - 根据用户反馈识别经验的知识盲区
   - 生成 enhance 提案补充缺失的经验
   - 再次提示用户验证
5. **迭代上限**：同一经验的验证-迭代循环不超过 3 次，避免无限循环；超过上限后提示用户手动审查经验

## 已沉淀的经验

### 验证机制设计
- 验证的核心是"无上下文复现"：新 Agent 只有框架 MD 文件，没有原会话的交互历史
- 可读性 ≠ 可复现性：经验在人读起来可靠，不代表新 Agent 能据此完成任务
- 验证失败的价值：失败暴露的经验盲区，正是需要补充的关键信息
