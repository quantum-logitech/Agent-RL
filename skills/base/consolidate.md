# Skill: consolidate

## 描述
整理 Agent 框架中所有 Skill 的「已沉淀的经验」章节，将按时间戳线性排列的经验条目按特性归类重组，去除时间戳和来源标注，使经验按主题组织，提升可读性和可维护性。

## 触发条件
- 用户要求整理、归纳、归类 Skill 中的经验沉淀
- 用户说"整理经验"、"归纳经验"、"归类经验"、"整理 Skill"、"经验去重"等
- 用户显式要求对 `## 已沉淀的经验` 章节进行重构

## 行为规范
1. **扫描目标**：递归扫描 `skills/` 目录下所有不以 `_` 开头的 .md 文件（含子目录），定位每个文件中的 `## 已沉淀的经验` 章节
2. **逐文件归类**：对每个文件的已沉淀经验：
   - 去除时间戳 `[YYYY-MM-DD HH:MM]` 和来源标注 `（来源: ...）`，**保留条目原始语义，在保留原始语义的基础上可以改写或精简内容**
   - 按特性/主题归类（如：触发条件相关、环境配置相关、工具用法相关、常见陷阱相关等，具体类别根据实际内容归纳）
   - 合并语义重复的条目，保留最完整的表述
   - **跨章节融入**：如果经验条目的主题与 Skill 中已有的章节（如触发条件、行为规范）一致，应将经验语义融入该章节，而非在已沉淀的经验中新建类别
   - **语义融合而非机械追加**：融入已有内容时应将经验自然地融入原文叙述中，而非以条目形式追加到章节末尾
   - 归类后的格式为：
     ```
     ## 已沉淀的经验

     ### <类别1>
     - <经验内容>
     - <经验内容>

     ### <类别2>
     - <经验内容>
     ```
3. **展示变更**：向用户展示每个文件的归类方案（归类前 vs 归类后），等待用户确认
4. **用户确认后写回**：用户确认后，将归类结果写回对应 Skill MD 文件
5. **用户拒绝则放弃**：不做任何修改

## 已沉淀的经验

### 归类原则
- 类别名称应简洁明确，反映经验的主题而非时间线
- 归类粒度适中：过粗则失去归类意义，过细则条目过于分散
- 当单条经验涉及多个主题时，归入最核心的主题类别
- **优先融入已有类别**：新条目优先归入语义一致的已有类别，仅当内容无法归入任何已有类别时才新增主题，避免碎片化

### 去除内容
- 时间戳 `[YYYY-MM-DD HH:MM]`：归类后时间线不再有意义
- 来源标注 `（来源: ...）`：归类后经验本身比来源更重要，来源信息可在 git 历史中追溯
