# 反思提炼协议

你负责从交互历史中提炼关键建议，驱动 Agent 自我进化。这是 Agent-RL 的核心机制。

## 触发条件

当以下任一条件满足时，启动反思提炼：
- 用户对结果进行了纠正或补充
- 用户表达了偏好或风格要求
- 同类问题出现 3 次以上相似的处理模式
- 用户显式要求沉淀某条经验（说"反思"、"提炼"、"沉淀"、"总结经验"）
- 路由无法匹配到任何 Skill（此时将请求本身作为新 Skill 种子）

## 提炼流程

1. **回顾交互**：回顾本次会话中的对话轮次
2. **识别关键信号**：
   - 用户纠正 → Skill 的知识盲区 → 提案类型: enhance
   - 用户偏好 → Skill 应内置的默认行为 → 提案类型: enhance
   - 重复模式 → 值得独立为新 Skill → 提案类型: new
   - 多个 Skill 有重叠行为 → 需要合并 → 提案类型: merge
   - 无匹配 Skill → 该类请求需要新 Skill → 提案类型: new
3. **生成提案**：每条提案必须包含：
   - **类型**: enhance / new / merge
   - **目标 Skill**: 要增强或合并的 Skill 名称（new 类型时为新 Skill 名称）
   - **建议内容**: 具体要沉淀什么
   - **理由**: 为什么值得沉淀
   - **证据**: 来自交互的证据（引用具体对话内容）

## 展示格式

向用户展示提案时，使用以下格式：

```
📋 进化提案

[1] 类型: new | 目标: <新skill名称>
    建议: <建议内容>
    理由: <为什么值得沉淀>
    证据: <交互证据>

    → 接受(a) / 放弃(r) / 修改(m)?
```

## 用户审视后操作

### 用户选择「接受」
- **enhance**: 打开目标 Skill MD，在 `## 已沉淀的经验` 部分追加：
  ```
  - [YYYY-MM-DD HH:MM] <建议内容>（来源: <证据摘要>）
  ```
- **new**: 在 `skills/` 下创建新 Skill MD 文件，结构为：
  ```markdown
  # Skill: <名称>

  ## 描述
  <建议内容>

  ## 触发条件
  <从交互中推断>

  ## 行为规范
  <从交互中推断>

  ## 已沉淀的经验
  - [YYYY-MM-DD HH:MM] <建议内容>（来源: <证据摘要>）
  ```
- **merge**: 在目标 Skill MD 的 `## 行为规范` 部分追加合并内容

### 用户选择「放弃」
- 不做任何修改

### 用户选择「修改」
- 根据用户修改意见调整提案内容，然后按「接受」流程执行

## 约束

- 每次最多 3 条建议
- 每条建议必须有证据支撑
- 不提出没有交互证据支撑的建议
- 写回 MD 时保持文件格式整洁
